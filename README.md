# Лесенка — расчёт наклонного подъёмника

Рабочая копия калькулятора [лесенка74.рф](https://лесенка74.рф): по геометрии
лестницы считает параметры наклонной подъёмной платформы и проверяет, проходит
ли подъёмник в 12 вариантах исполнения (EasyTrap и НПУ).

## Как открыть

Никакой сборки не нужно — это статический сайт:

```powershell
start index.html
```

Либо локальный сервер, если браузер капризничает с `file://`:

```powershell
python -m http.server 8000
# http://127.0.0.1:8000
```

## Что внутри

| Файл | Назначение |
|---|---|
| `index.html` | оболочка: шапка, меню, три экрана (форма, результат, карточка модели) |
| `js/engine.js` | расчётное ядро, без зависимостей, годится и для Node |
| `js/app.js` | форма на 30 ступеней, роутер на `#/`, таблицы результата, схемы |
| `css/style.css` | оформление: Inter, Bootstrap 5.2.3 с CDN, узкий контейнер |
| `tests/engine.test.js` | 18 сверок с замерами живого калькулятора |

Экраны повторяют поведение оригинала:

- **форма** — до 30 ступеней (высота подступенка и длина проступи), длина нижней
  площадки, ширина марша, длина верхней площадки, четыре варианта пандуса,
  переключатель «Укороченная площадка НПУ»;
- **результат** — угол лестницы, высота подъёма, длина подъёма, затем две таблицы
  (EasyTrap и НПУ) с матрицей «проходит / не проходит» и четырьмя параметрами
  платформы;
- **карточка модели** — `#/et_passage_to_wall` и остальные 11 маршрутов: схема,
  статус и все размеры.

## Модель расчёта

Обозначения: `h_i` — высота ступени, `l_i` — длина проступи (у последней ступени
проступи нет), `R = Σh_i`, `H_max = max h_i`.

Воспроизводится точно (сверено на десятках расчётов, расхождение 0–3 мм):

```
угол лестницы   A  = atan(R / (Σl_i + l_последняя))
высота подъёма     = R
длина подъёма      = Σ √(h_i² + l_i²)
угол EasyTrap   αэ = floor(угла НПУ), не выше 30°
угол НПУ        αн = A (+ сдвиг от пандуса), не выше 30°, округление до 0,1°
длина пути         = R / sin(α)
минимальная площадка (EasyTrap) = (H_max + 51) / tg(αэ) + 1174 + поправка
минимальная площадка (НПУ)      = (H_max + 40) / tg(αн) + 1222,5 + поправка
поправка = (1/tg(α) − 1/tg(A)) · (R − 2·H_max)
"боковая" площадка = минимальная − 174 (EasyTrap) / − 145 (НПУ)
```

Проверка проходимости — по двум условиям: ширина марша не меньше порога варианта
(1100…1450 мм у EasyTrap, 1090…1250 мм у НПУ) и нижняя площадка не короче
минимальной.

Приближённо (подобрано по сетке замеров, не выведено из геометрии):

- сдвиг угла от удлинённого пандуса (+50/+100/+150 мм) — эмпирическая формула,
  на лестницах короче 7 ступеней может ошибаться до 1°;
- лестницы с разными длинами проступей: прогон считается как сумма проступей
  плюс последняя из них, у оригинала правило для неровных проступей не выведено.

Матрица «проходит / не проходит» может расходиться с оригиналом на граничных
значениях (ширина или площадка ровно на пороге).

## Тесты

```powershell
node tests/engine.test.js
```

Ожидаемый итог: `tests 18`, `pass 18`, `fail 0`. Запускать именно файл, а не
`node --test`: в песочнице DSH последний не может породить дочерний процесс.
